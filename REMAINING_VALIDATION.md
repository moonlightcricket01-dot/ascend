# ASCEND — validation still requiring a real device or qualified reviewer

The functional offline build has been expanded as far as can be honestly validated in this coding environment. The items below are not missing online infrastructure; they require a physical device, an independent reviewer or production assets. Do these before describing the app as safety-reviewed or production-certified.

- [ ] Install the PWA on the target Android browser/device; test first load, airplane-mode relaunch, refresh, update and uninstall behavior.
- [ ] Test a current desktop browser, narrow mobile screen, tablet and landscape layout.
- [ ] Test local data after browser restart, storage pressure, browser cleanup and device reboot.
- [ ] Test normal JSON and encrypted backup export/import on a second browser/device; test wrong password and damaged file handling.
- [ ] Test local notification permissions and document browser/OS closed-app restrictions.
- [ ] Obtain qualified fitness-professional review of all 105 exercise entries, substitutions, cue wording, program templates and safety warnings.
- [ ] Conduct screen-reader and keyboard-only review with real assistive technology; complete a WCAG audit.
- [ ] Conduct independent security/privacy review of local browser storage, backup encryption, import validation and reset behavior.
- [ ] Run usability sessions to validate whether onboarding, planner, workout player, RPG rewards and Part 27 are understandable without guidance.
- [ ] Decide whether to commission additional original character art, animation, voice acting and music. The current SVG/text package is the offline functional alternative, not a full animation studio deliverable.

Until those checks are performed, call this a feature-rich offline development build, not a fully certified production app.
